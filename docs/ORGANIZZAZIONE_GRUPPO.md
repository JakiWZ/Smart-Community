# Organizzazione del gruppo

Serve per lavorare bene insieme; non va consegnato. Nomi e ruoli si scrivono nel Project Brief.

## Ruoli

| Ruolo | Di cosa si occupa | File principali |
|---|---|---|
| Logica Python | Funzioni, regole, calcoli, menu | `main.py`, `logic.py` |
| Dati e test | Dati di input e output, casi di prova | `storage.py`, `data/`, `output/`, VALUTAZIONE_FINALE.md |
| Frontend | Pagina che carica il file esportato, tabella, messaggio d'errore | `frontend/index.html`, `frontend/app.js`, `frontend/style.css` |
| Coordinamento e documentazione | Kanban, brief, README, pitch | MONITORAGGIO.md, PROJECT_BRIEF.md, `README.md` |

In tre unite Frontend e Coordinamento e documentazione. Ognuno deve saper spiegare il flusso completo, dal terminale al file fino alla pagina.

## Condividere i file

- Usate una sola cartella del gruppo.
- Ogni file ha un responsabile.
- Dopo aver unito il lavoro provate `python main.py`.
- Fate una copia di sicurezza prima di una modifica grande.

## Presentazione

- Parlate tutti: ognuno presenta una parte che sa spiegare.
- Scaletta: problema e target; obiettivi e MVP; demo da `python main.py`; export e caricamento del file; un test di errore; risultato; limite e miglioramento.
