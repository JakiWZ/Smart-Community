# Python Innovation Hackathon — From Idea to Working Application

## Missione

In un gruppo di 3–4 persone trasformate un problema concreto in una piccola applicazione. Il prodotto deve funzionare dal terminale, gestire dati e produrre risultati leggibili attraverso un frontend HTML/CSS/JavaScript. Potete inventare dati sintetici coerenti con il problema.

Il lavoro si sviluppa in due giornate: ideazione e primo prototipo; completamento, verifica e presentazione. La guida docente organizza gli incontri. Non scegliete il progetto in base al numero di tecnologie: sceglietelo in base a un bisogno chiaro e a un risultato verificabile.

Ogni scheda propone più direzioni possibili. Il gruppo deve scegliere una sola idea, precisarne il destinatario e formulare una domanda: «Come potremmo aiutare ___ a ___ attraverso ___?». Una funzionalità deve rispondere a questa domanda, non soltanto aggiungere schermate.

## Organizzazione del gruppo

Assegnate responsabilità per logica Python, dati/test, frontend e coordinamento/documentazione. Con tre componenti unite le ultime due responsabilità (Frontend e Coordinamento e documentazione). Le responsabilità non sono compartimenti chiusi: ogni componente deve saper spiegare il flusso completo e contribuire a una prova integrata. Ruotate chi esegue la demo durante i checkpoint. Per ruoli, condivisione dei file e presentazione leggete ORGANIZZAZIONE_GRUPPO.md, nei materiali per gli studenti.

## Dall'idea alla consegna

1. Identificate problema, target e motivazione; compilate il brief.
2. Definite obiettivi osservabili e tre operazioni principali. Stabilite cosa resta fuori dal MVP.
3. Disegnate dati di input, risultati di output e chiamate tra file Python. Pianificate attività ordinate e responsabili.
4. Realizzate un flusso completo semplice, dal terminale al file e alla dashboard, prima di aggiungere funzioni.
5. Aggiornate il Kanban e confrontate piano e risultati nei checkpoint CP1, CP2, CP3.
6. Bloccate le nuove funzionalità, eseguite i test, correggete e valutate ciò che avete ottenuto.
7. Presentate problema, MVP, prova dal vivo, risultati e un miglioramento motivato.

## Consegna del gruppo

Consegnate una sola cartella con codice Python avviabile, `data/`, `output/`, `frontend/`, README, i quattro modelli compilati, elenco dei test con atteso/osservato ed eventuale dichiarazione AI. Includete almeno un output riproducibile e le istruzioni per rigenerarlo. Il README deve indicare i nomi reali dei file da caricare nella dashboard.

La prova finale parte da `python main.py`, mostra almeno un'operazione con input, genera un risultato e lo carica manualmente nel frontend. Nessuna connessione tra browser e Python è necessaria. Consultate i [requisiti](REQUISITI.md) prima di ampliare il progetto.
